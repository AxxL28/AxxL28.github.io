01 • GAME SUMMARY

Building a multiplayer action game

Blood & Lineage was developed as an 8-month multiplayer-focused capstone project with a team of 11 developers.

The game combines fast-paced Musou-style combat with roguelike progression, procedural level generation, unique playable classes, and cooperative multiplayer.

My primary focus was gameplay programming. I designed the core ability architecture, implemented 13 of the project's 16 unique abilities, worked on multiplayer replication, and helped lead the programming team.

ABILITY SYSTEM

Use Case Walk Through

I designed a reusable ability architecture with some help from Unreal's Gameplay Ability System that allowed different character classes to share the same underlying system while still having completely different gameplay identities.

The following walkthrough shows how an ability moves through the system when a user utilizes one of there abilities

01

Player activates an ability

The player presses an input mapped to one of their character's abilities. The input is passed into the character's ability system and begins the activation process.

02

Ability activation

The ability checks whether it can currently be activated, including cooldowns, gameplay state, and other activation requirements.

03

Determine the target

The ability determines what it should affect based on its configured target type. This can include the player, a single enemy, an area, or a cone.

04

Execute gameplay logic

Once the target is determined, the ability executes its gameplay logic. Depending on the ability, this can involve damage, healing, buffs, debuffs, movement, or other gameplay effects.

05

Server-side execution

In multiplayer, gameplay-critical actions need to be handled with the server in mind so that clients cannot independently determine authoritative gameplay results.

06

Replicate gameplay state

Relevant gameplay state, effects, animations, or events are replicated so connected players receive the correct result.

07

Gameplay result

The ability completes its execution and the resulting gameplay changes are reflected across the connected players.

05 • CHALLENGES

Problems worth solving

01

Designing a reusable ability system

Multiple characters needed completely different gameplay identities while still sharing the same underlying architecture. The system needed to be flexible enough to support new abilities without creating duplicated gameplay code.

02

Multiplayer consistency

Gameplay could not simply execute locally. Abilities, attacks, animations, effects, and gameplay state needed to behave consistently between the server and connected clients.

03

Debugging a large team project

Working across a team of 11 developers meant that gameplay systems frequently interacted with systems created by other programmers. Debugging often required tracing problems across multiple classes and systems.
